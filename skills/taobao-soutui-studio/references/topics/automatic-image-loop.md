# 八图自动生成与验收循环

## 节点合同

输入：已确认的八镜头表、产品和方向资产、每镜头任务与验收要求、Nano Pro 当前合同、实际报价及本轮费用上限。输出：八张已验收候选或明确缺口、每次任务与图片证据、最终整组检查。此节点止于本地候选和复盘；随后进入 N5 写整组文案。

用户授权完整自动节点时，应用可在本轮预算内完成质量修正。每镜头最多三次真实提交（首次加两次修正），全组最多24次。单步调试沿用用户指定范围。先按实时单张报价设定并记录预算，累计已知费用与未决任务预留费用；预算不足暂停。未知结果始终跟随原 task，禁止用质量重试绕过任务恢复。

## 执行方法

1. 初始化 `scripts/image_loop.py init --root RUN/loop --input seed.json`。seed含 authorized、authorizationEvidence、creditBudget、八个唯一 shots（id、purpose、acceptance、spec）。spec含 prompt、model、ratio、resolution、有序 references（path、role、version、sha256可省，由脚本计算）。模型与资产来源由调用者核实。
2. 逐镜头准备简洁提示词，以确认的实图锁定产品、人物、环境和风格。按语义角色解析实际参考文件，合并同一图片的多重职责，提交前校验有序路径、角色、版本与摘要；重复图片由脚本拦截。人物抱持、穿戴或操作等依赖相对大小的镜头设 scaleRequired=true，将经原图核实的尺度图作为 relative-scale-only 实际传入，图中人物和场景仅供尺度对照。优先选用去背景或中性背景的尺度资产；旧场景原图用于核验。每张参考写自然语言 instruction，按实际上传数组调用 reference_prompt(references, scenePrompt) 生成“参考图N：用途”，保留 scenePrompt 与完整 prompt；其他新镜头也采用这一编号结构。动作写清单一可见状态；场景与人物身份定稿后，镜头变化保持同版资产。
3. 按下文做第三方视角的提示词预检。通过后逐图 dry-run。`begin` 输入 shotId、estimate，先预留次数与费用，再通过媒体CLI提交一次。无 task ID 的中断记录为 recover-task，先查媒体历史核对提交结果。`attach` 输入 shotId、taskId、status，成功附 cost 与 artifact（path、sha256）；未知/失败留在恢复节点，明确服务失败由能力合同诊断。
4. 真实查看结果与对应资产，整体检查一次；疑点可追加一次局部检查。review输入 shotId、sha256、inspected=true、reviewer、六项scores和适用的gates，每项必须附具体可见evidence。脚本计算分数，Agent承担视觉判断；不得用脚本字段完整替代实图验收。
5. 不通过先写根因、修正目标与参考调整理由，再用 revise 提交 shotId、diagnosis、changeReason 和新 spec。新提示词表达完整当前需求；保留旧记录。通过即停止该镜头；三次仍未通过记 exhausted，继续独立镜头，最终如实交付缺口。证据缺失回上游补资料，不能反复生成猜商品。
6. 全部通过后并排检查八图人物、服装、产品、房间、尺度及信息互补，set-review输入 evidence 与 reopen镜头ID列表。只重开受影响镜头，原计数保留。通过的整组以 reopen=[]提交后才可 export；export再次核对文件摘要。

所有写事件带 `--expect-revision N --input event.json`；status只读。脚本独占锁与追加修订，恢复沿用同一root。最多一次总体检查加必要局部核对作为常规路径；无法判明的关键项记unknown并补证。观察与决策存项目，不写入Skill。

## 迭代结束后的检查报告

所有镜头通过并完成整组复核，或所有镜头均已通过或用尽尝试次数时，运行 `python3 scripts/image_review_html.py --root RUN/loop --output RUN/07_复盘/生图复盘.html`。有待重试、待补证或待恢复任务时继续相应分支，已有首轮预览可以独立留存。报告读取每次实际提交的 spec 和对应图片、视觉验收记录。每个镜头使用一个折叠框，按时间顺序列出各轮参考图、原样提示词、成图和验收分析。六维评分、硬门证据与下一次实际提交的调整理由随对应轮次展示。以最终评分与验收状态标识镜头，耗尽次数的镜头保留缺口。复盘 HTML 单独存放在运行目录的 `07_复盘`，通过相对链接展示原图，正式素材目录仍只放最终图片与发布文案。

## 提交前第三方审读

把镜头的目标、最终提示词和将按序上传的实际图片作为独立输入。审读者以首次接收任务的生图执行者身份，逐句把文字落实为同一帧，复述画面中谁在哪里、相机在哪里、主体怎样放置和接触，以及每张图提供什么证据。核对整段累积后的约束也能同时成立。审读以当前输入为准，提示词编写者的解释不补充为隐含条件。

- **参考职责。** 将图号与实图逐一对照。区分实物形态、相对尺度、局部纹理、人物身份、房间和摄影风格。遇到不同朝向、动作或背景时，写清每项视觉事实由哪张图决定。
- **实际可拍。** 在不改变实物几何与尺度的前提下，推演构图、摆位、支撑、接触、视线、光源与可见信息。区分相机取景和主体本身的变化。读到必须猜测、拉伸物体、隐藏必要证据或满足互斥摆法才能继续的句子时，判为阻断。
- **记录与放行。** 每次审读记录镜头ID、原句或对应图号、冲突理由、最小改写以及复读结果，绑定最终 prompt 与有序参考摘要。遇到冲突先回到镜头任务和确认证据，优先改写提示词或收窄参考职责，再从头复读。上游证据不足且影响商品真值时，补齐证据后再审。仅当前输入审读通过才可 dry-run 和 begin，输入变化重新审读，审读改稿不占真实提交次数。最终审读记录随 spec 归档。生图后的视觉评分仍独立执行。

全新重跑建立新的 loop；首轮只取确认的规划、原图证据和定稿资产，重新编写每镜头输入。质量修正只诊断本轮对应镜头的结果。

## 六维评分

每维0—5分，允许半分。5=清楚满足；4=满足用途、有轻微不影响判断的偏差；3=明显需修；2=重大偏差；1=基本不成立；0=缺失/错款。权重依次为 product商品一致性30、use场景与使用20、plan镜头任务15、continuity全组连续性15、aesthetics自然美观10、salience商品重点和信息10。总分=sum(分数/5×权重)。通过需总分≥85，商品、使用、任务各≥4，所有硬门通过。

七项硬门：identity商品身份/结构、count本镜头商品数量、physics身体/接触/支撑、continuity确认的人物与主要空间身份、requiredContent必需信息、overlay新增广告覆盖层、technical文件可读及清晰度。每项 pass/fail/unknown 附可见事实；关键unknown进入needs-evidence，补充检查后对同一文件重新review，补证前不允许付费修正。技术尺寸必须实际测量，服务请求参数不证明尺寸达标。scaleRequired 镜头另须提交 relativeScale 硬门：与原商品抱持证据并排比较，写出商品长度、粗细与可见人体参照的关系，考虑视角和遮挡。明显缩放记 fail，关键关系不可辨记 unknown。人景一致性另核对主要家具与空间布局。单镜头重做沿用同一参考编排和验收合同，单独留档。

商品结构与数量、明显错款、主要身份变化、错误操作、关键内容缺失不能被审美分抵消。局部细节和遮挡按真实参考及镜头任务判断；用户接受过某图不自动放宽其他图。确有用户授权的局部容差应写本轮验收卡，保留原始商品证据。分数是本应用内部筛选，不声称平台评级或真实购买效果。

## 交接与持久化

loop保存各镜头全部attempts，应用商品台账登记新batch与loopRoot，仅将最终通过的每镜头代表图加入candidates。不得用失败尝试填满八候选名额。费用、任务ID、提示词、有序实图及版本、SHA、评分证据、修正理由、整组复核全部可追溯。人工选择和AI通过分别记账。整组不足八张不得标记完整完成，已通过图继续保留。

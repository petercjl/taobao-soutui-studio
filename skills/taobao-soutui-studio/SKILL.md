# 淘宝搜推图文制作

输入商品ID、可选项目根目录、本地主图或主图URL、方向与本次意图。输出商品台账、九个方向、每个已执行方向的八张候选图与一份发布文案 TXT，以及独立的过程档案与复盘。应用负责策划、生成、验收和交付；sealseek-media执行媒体任务，xhscli采集小红书证据，tbcli通过买家入口只读采集商品。图片选择、发布顺序与封面由用户决定，独立发布 Skill 承接发布。

每方向的图号对应镜头编号。只有用户已选择方向且授权生成时才执行该方向。

采用 [capabilities.json](capabilities.json)，Codex加载 [适配](adapters/codex.json)，其他宿主加载 [通用适配](adapters/generic.json)。缺失返回CAPABILITY_UNAVAILABLE，不运行时改写安装。跨宿主仅声明合同兼容，本机Codex有执行证据。

## N1 — 定位商品项目与恢复

从链接规范化商品ID。先检查用户指定目录，其次当前商品目录、当前工作目录的 `soutui-products/商品ID/`；存在则复用，禁止为同一商品例行新建随机项目。跨对话先用 [台账脚本](scripts/product_ledger.py) show读取最高版本，读取批次 runPath 下的运行清单，再呈现方向、运行目录、当前进度与下一步。其他工作目录需要用户给出原项目路径；不能声称仅凭商品ID自动搜索全机。同一ID多项目时列出候选，不自动合并。商品身份冲突时先核对来源。

新商品先初始化运行目录，九方向确定后按 [台账合同](references/topics/product-ledger.md) 准备 seed 并初始化商品台账。方向尚未确定而中断时，从商品目录下的运行清单恢复。JSON修订版为权威，HTML为按需生成的只读视图。每次修改带expect-revision，由脚本独占锁、校验并追加修订；冲突重新读取。项目数据与开发评估留在用户目录，运行不写Skill安装目录。

新创作在定位商品项目后、采集资料前，按 [运行目录合同](references/topics/run-layout.md) 调用 `scripts/creative_run.py init` 建立专用目录与运行清单。继续已有运行时直接使用台账中的运行路径。方向选定后将运行编号及相对路径登记到批次；每个方向独立归档。历史批次沿用原路径。

## N2 — 主图与事实

先复用台账已有参考：接受本地目录中用户提供的商品图片或明确图片URL；记录本地路径、URL、顺序、摘要、时间和角色。本地引用必须可读，URL下载后核对格式与内容；URL失效但原文件摘要有效时可继续。原始主图优先拷贝入项目的 `商品资料/主图/版本/` 以便迁移，项目内路径用相对路径。来源更新新增资产版本，已用参考保留。

缺少资料时精确解析逻辑Skill `tbcli`，通过其skill source加载完整当前canonical SKILL.md及本次item-summary/browser角色合同；发现当前version/capabilities，按当前Agent独立入口，用buyer item summary取得前五张真实主图。核对itemId及店铺，少于五张报告缺口，不重复凑数。可见外观、页面事实、用户信息与未知性能分开记录。

## N2.5 — 小红书定向研究与图文策划

按 [人物与场景策划](references/topics/audience-scene-analysis.md) 将人物场景设定与图组展示逻辑合为一个研究策划节点。输入商品事实、用户选择及原始素材，先列人物、空间、光色、动作、商品判断、封面及内页镜头必须回答的问题，人物部分按 [出镜者创作简报](references/topics/character-creative-brief.md) 提炼角色、情绪气质、生活状态与服饰妆发感觉，再按 [小红书观察](references/topics/xiaohongshu-visual-study.md) 选取证据；需要采集时加载 [xhscli交接](references/topics/xhscli-handoff.md)。输出可生图设定卡、出镜者创作简报、选定方向的候选镜头表、证据映射和资产需求表。环境部分按 [环境创作简报](references/topics/environment-creative-brief.md) 研究居住者、生活方式、人与家的关系及整体感觉，另交付简报和相应实图参考；用户指定与样本结论分别记录。先观察整篇笔记的封面与内页顺序、景别、机位、场景、接触动作及信息增量，再结合本商品编排候选镜头；普通批次规划八张，本次明确指定数量时按指令记录。资产制作以前完成初步镜头规划，确认资产以后再绑定文件与编译最终提示词。已有归档按问题使用，分析子集与至少11篇的归档覆盖分别记录。证据不足时由Agent补齐明确、合理的创作设定，逐项标注样本观察、Agent判断或用户指定及理由。涉及商品真值的关键缺口回N2。已指定方向直接产出该方向卡，其他创作选择交N3；用户要求先审时交付卡片并停在此处。

## N3 — 九方向规划与选择

进入知识节点才读取 [SCHEMA](references/SCHEMA.md)、[索引](references/index.md)、[近期变更](references/log.md)及 [策划路由](references/queries/plan-five-images.md)。检索问题：“同一真实商品有哪些不同需求与可信使用场景，九篇怎样提供不同的消费理由与视觉印象？”这些读取返回后才开始对应视觉分析；生图和文案知识按节点延迟加载。

九方向从 N2.5 的生活片段、人物与空间组合展开，各选定方向交付完整可生图设定卡。若策划仍需补证，返回 N2.5 按 [小红书视觉参考](references/topics/xiaohongshu-visual-study.md) 搜索、选样并记录画面决定，再返回方向规划。**小红书用于学习视觉风格、展示逻辑和发布文案的表达方式**。视觉观察用于策划画面，标题与正文观察用于 N5 组织一篇发布文案。商品外观、规格、配件与用法以已核实的商品资料为准，本商品原图用于事实核对和独立产品资产制作，素材按淘宝规则验收。

核对原图与事实表后，按 [推荐笔记策划](references/topics/recommendation-note-planning.md) 先为九个方向确定读者处境、商品发现与证据，再采用并细化 N2.5 已有的选定方向封面与八图分工；选定方向缺镜头方案时先返回 N2.5 补齐。 续做历史方向时，也先在当前批次策划中明确适合谁、为什么值得考虑、如何判断是否适用。历史方向名只提供主题，按当次推荐理由确定标题和叙事。若现有策划只回答“怎么操作”，先提炼商品选择或使用价值，再排镜头。

查看原图并创建事实表和九个稳定方向ID，按 [生活任务策划](references/topics/direction-planning.md) 先写人群、生活任务、具体使用问题、商品角色和可核实信息，再安排环境、道具与摄影。不同方向以内容增量区分，画面差异由实际任务自然带出；同一可信厨房可复用，不要求九种摄影风格或固定数量的视觉差异。创作目标为真实可信、好看且让人向往的商品使用体验；商品准确、使用成立、画面美观和决策价值同时满足，具体审美方法见生活任务策划页。家庭使用场景统一采用当代中国普通家庭住宅，具体住宅空间、装修家具、生活痕迹和操作区见生活任务策划页；涉及其他适用空间时保持中国本地生活语境并按商品真实用途规划。每方向记录visual、参考角色及sceneContract（具体空间、参与者关系、操作状态、摄影者位置与高度、现实光源、必要物件）。生成前将本方向与最近已执行代表图并列，写出不依赖标题的可见区别；同一台面、同一窗边手部略俯拍仅改步骤时按同情境变体处理。生活内容与可见情境都明确后，记录visualIntent（希望感受到的生活体验、商品视觉重点、光色与构图、克制的环境线索）再提交。每方向保留visual与参考角色；展示九方向由用户选择，既有明确选择可直接采用。重规划使用replan保存旧版本，历史批次仍可按原记录查看。

用户明确要求双机位资产测试时，核对该方向可生图设定卡后进入 N4 资产流程，按两张样图的授权范围执行。用户仅要求单张调试时，进入单张调试分支：先给出一个生活情境的策划与提示词，只在明确试图授权内生成一张，kind=pilot、targetCount=1独立记账。用户认可单张后仍按其后续范围执行，不自动生成八张。普通批次继续每方向八候选，方向和候选数量均以本次指令为准。

## N4 — Nano Pro候选生成

读取 [生成路由](references/queries/generate-and-review.md)和 [SealSeek交接](references/topics/sealseek-generation.md)。本应用明确用npm包 `@petercjl/sealseek-media-cli`；精确解析逻辑Skill `sealseek-media`，完整读其当前canonical SKILL.md及当前宿主适配，使用该安装scripts/run.mjs。默认显式 `--model nano-banana-pro`；用户本次明确要求其他模型时保留其选择并验证模型合同。此路由不随宿主默认imagegen改变。

从当前已确认的可生图设定卡及方向包读取人物、环境、光色、参考顺序、职责和样图验收条件，目视核对实际参考文件，读取已确认候选镜头表及资产需求表，再制作资产。镜头按任务、角度和可见信息推导所需参考，合并重复需求并记录来源缺口。进入候选生成前执行 [方向资产定稿与双机位验收](references/topics/direction-assets.md)。先通过依赖 Skill `product-asset-set` 获取并核验定稿产品资产包，再绑定本方向的环境、人物和风格。人物先按简报用开放描述探索整体造型，用户确认后从实图冻结脸发与穿搭；已定稿身份在后续镜头引用同版人物资产。环境资产先依据简报与参考以开放提示词生成，先验收氛围，再检查镜头可用性；用户确认后才从实图冻结家具、布局和光色，作为后续镜头的具体空间合同。先出一张场景图检查商品、人物、环境和尺度，通过后按授权出第二机位，合格样图可计入八张；用户指定双样图测试时，交付资产与样图后停在验收节点。双样图计入同一普通批次，targetCount=8，记录实际授权范围与测试状态。

用户授权完整自动八图节点时，执行 [自动生成与验收循环](references/topics/automatic-image-loop.md)：每镜头最多三次真实提交，全组最多24次并受本轮预算约束；脚本约束次数、费用、状态和文件，Agent实际看图评分与调整参考。单步模式按用户指定数量执行。capabilities --live及models show --live后，每个镜头的首次和修正提交均须完成第三方视角的提示词预检，再逐图 dry-run 和提交。全新重跑以确认的镜头规划、商品事实和定稿资产重新编译首轮输入，使用独立台账。每方向候选及单张调试分别有候选ID、prompt、有序参考及角色与版本、模型、ratio/resolution、task_id、费用与本地结果。每张提示词分开写实物参考、全组风格和单张信息任务，再安排动作、镜头与光线。提交前核对封面候选能否用画面说明推荐理由，八张候选是否各自补充有效信息。逐图从已核验的产品资产包选用对应全貌和必要细节，分别写明规格、接触关系及动作状态。送入模型前目视每张参考，核对产品身份和场景的参考职责。把营销覆盖层和商品本体印刷分别验收。具有刻度、规格或标识的商品须逐图放大与原图核对，关键信息错误的图不得计入可用成品。搜推图按自然推荐摄影制作，以真实场景、使用关系和完整商品提供决策信息。图面使用干净摄影构图，保留实物本身的标识和印刷。详情页大标题、角标、卖点条、广告口号、价格和任何新增覆盖文案均为不合格，逐图目视拦截。发布标题和正文独立写入 TXT。生成前对照方向规划、确认资产和实际提示词，核对本方向的生活任务、商品角色、真实操作及内容增量，再按sceneContract将具体空间、参与者关系、操作状态、摄影者站位与镜头高度、现实光源及必要物件写入每条提示词。将已规划的中国家庭环境具体线索写入实际提示词；提交前核对这些内容来自本方向而非通用厨房模板。产品资产负责商品身份，方向资产负责环境、人物和摄影风格。每次任务提交后立即用task事件记入台账；逐图完成后用add-candidate登记带SHA256的文件。服务失败、超时或未知跟随原task恢复。成功出图后的质量修正按自动循环的授权、预算与尝试上限执行；仅最终通过图进入八候选，所有尝试保存在loop台账。八张尚未完成时保留部分结果和缺口。 所有镜头迭代结束后，从实际尝试台账生成独立的生图复盘 HTML，按镜头折叠历次参考、提示词、成图与评分。复盘与正式交付目录分别保存。

采用小红书参考的方向，逐图对照项目记录验收风格与展示逻辑，并独立核验商品准确性。实际查看商品一致性、主体完整、正确使用关系、自然生活感、信息价值与文字，按生成检查页单独记录chinaHomeContext，区分环境可信、待确认与不符合，并列出画面证据；同时按生成检查页记录visualAppeal和productSalience，核对观感吸引力、第一视觉与商品辨识；记录建议及问题；用户决定最终选图；自动模式由约定验收门槛进行有界质量修正，单步模式交用户判断后续。真实功能宣称和明确操作关系仍需核对；用户接受整体画面不能自动证明未核实性能。原图保留，技术格式检查与用户视觉选择分开。请求3:4/2K后测量实际尺寸；近似比例不声称精确满足发布合同。

## N5 — 发布文案与本地交付

按 [文案路由](references/queries/write-copy.md) 读取本次小红书归档原文、批注、商品事实及实际合格图组，写一篇独立的标题、正文及可选话题。草稿与原文并读记录保存在 `05_文案过程`。写稿和交付以整组候选为依据。

按 [运行目录合同](references/topics/run-layout.md) 完成复盘与交付。八张通过整组复核后，从台账导出按镜头编号的八张图和 UTF-8 `发布文案.txt` 到 `06_交付`。迭代结束后的 HTML 在 `07_复盘`。迭代耗尽且存在缺口时，复盘和运行清单标记部分完成。单张调试交付对应样图。向用户提供本次交付和复盘路径，由用户决定选图、顺序与封面。

## 分支与验证边界

缺参考回N2，未选方向回N3。任务未知按依赖合同恢复；版本冲突重新读取；锁存在先核实活动进程；资产丢失按已记来源恢复并比对原摘要。追加创作建立新运行；中断继续原运行。静态检查、本机脚本测试、实际创作样例与独立回归分别报告。

# 方向资产定稿与双机位验收

选定方向后，输入已确认可生图设定卡、商品实物参考、sceneContract、visualIntent 和镜头分工。先核对已确认候选镜头表和资产需求表，按镜头所需证据制作产品资产，再定环境、人物与风格版本，最后绑定实际文件并编译每张图的参考输入。缺初步镜头规划时返回 N2.5。

- 环境图读取 [环境创作简报](environment-creative-brief.md)，用居住者、生活方式与整体感觉的开放提示词及所选实图生成环境候选。先验收真实好看、有生活气息且符合方向的气质，再检查镜头所需空间。确认后从实图记录家具、布局、光色并冻结版本；必要时基于同版补充视角。
- 人物图读取 [出镜者创作简报](character-creative-brief.md)，用角色、情绪气质、生活状态和服饰妆发感觉的开放描述生成定妆。先审整体选角与商品环境适配，再审脸发、服装与身体取景是否清楚完整。确认后从成图冻结人物身份与穿搭，出镜镜头引用同版人物资产，纯商品和环境镜头省略人物图。
- 风格图交代光向、色调、对比和摄影质感。选择主体中性的参照，或采用已验收样片。风格参考只控制摄影表达。
## 独立产品资产包

在 N4 定稿场景并编译候选参考前，按精确名称 `product-asset-set` 从宿主目录或配置的 Skill 根目录解析依赖，完整加载其当前 `SKILL.md`，从依赖自身目录读取资源。执行依赖主线，输入已核实商品原图、目标款色、形态基准及各镜头所需的产品证据，要求完整主体的中性背景全貌图，按需补结构、纹理或标识。对全貌、尺度、结构、材质、标识和使用关系逐类记录是否需要、理由及所服务镜头，具体图种数量和画幅由依赖按证据与需求决定。尺度图可以保留必要人物或参照物，记录其用途。原图保留为实物证据。由依赖决定制作、复核和定稿方式，按当次授权处理需要生成的步骤。

依赖合同为产品资产图组交接协议；加载当前依赖声明的版本，当前使用 v2，旧 v1 图组按依赖兼容能力读取。使用依赖当前文档声明的 `node scripts/asset-guide.mjs check <资产说明.txt>` 核对版本目录的 PNG、角色、像素尺寸和 SHA-256，另以目视检查实际内容。原图与资产之间须核对轮廓、比例、材质、结构和可见标识。资产定稿依据为用户确认，已定稿的同款同版本可按摘要复用。记录款色、版本、资产说明路径、原图来源、确认依据及校验结果，并返回 N4。缺依赖报 `DEPENDENCY_MISSING`，合同不兼容报 `CONTRACT_UNSUPPORTED`。证据不足、文件校验失败或资产待确认时，留在资产节点处理。

候选图优先用中性背景的 `overall` 做商品身份参考，按镜头增选干净细节。尺度图若带原详情页的沙发、背景或模特，留作策划与验收对照，避免随参考进入候选生图。原详情页也只留作证据。沙发、人物、布局与光色从方向独立规划，依据新方向的环境、人物及风格资产。进入双样图前，将新环境资产与商品来源场景对照，检查关键家具和布局是否符合本方向的创作选择。

人物定妆先对照方向包的出镜者设定，核对呈现的年龄感、穿搭、姿态、场景角色和动作是否符合。即使脸和服装可稳定复用，人物与方向不符也停在定妆节点，记录差异并按授权调整。符合后再冻结人物资产并进入双机位。

先逐张目视验收并冻结资产。按商品→方向→批次保存在项目内。记录每项角色、版本、文件路径、摘要、来源和生成任务；批次通过 planPath 指向资产记录，每张候选保存实际有序参考及角色和版本。可跨批次引用明确的既有版本。更换资产创建新版本，保留历史记录。

提示词为各参考图声明独立职责，再写本张的视角、动作及取景。先出一张能看清关键资产的场景图，检查商品、人物、环境和尺度；通过后按授权出第二张不同机位或动作样图。并排核对同一家具的扶手、靠背、分缝和空间关系，出镜者脸、发型和服装，商品比例、材质及部件，以及光色。核对两图分别提供可辨的使用信息。发现身份漂移或结构变化，定位对应参考或镜头并记录缺口；额外生成按当次授权执行。普通批次通过后再完成剩余六张。测试批次保留资产与样图供用户复核，随后回到 N4 继续获授权的镜头。

规划下一方向时记录新的读者判断与可见场景差异；同篇内用机位、动作和景别推进叙事。
